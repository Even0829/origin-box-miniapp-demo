# 引元移动端交互 Demo

本目录为独立静态交互 Demo。前期讨论与开工依据见 原项目知识库中的 `architecture/origin-box-miniapp-experience.md`，已完成页面的最终规格见 原项目知识库中的 `specs/origin-box-miniapp-prd.md`；本文只记录运行、素材与当前实现情况。新版首页视觉与素材来源：[Figma 599:411](https://www.figma.com/design/ILpT5meWxj9quaJgdvXOqT/Untitled?node-id=599-411)。不影响电视 Demo。

## 运行

在本仓库目录执行：

```sh
python3 -m http.server 4173 --bind 127.0.0.1
```

打开 [本地预览](http://127.0.0.1:4173/)。无需安装第三方运行依赖。逻辑视口为402×874，桌面居中展示；当前仍为静态Web交互原型。

首次使用入口为 `first-use.html`。普通入口刷新恢复预置状态，账号隔离样例可能在同一浏览器会话中续接。

本仓库只包含Demo；正式规格、设计任务及验证证据保存在原项目知识库，文中的对应说明仅作来源指引。

## 账号、统一成员与邀请体验（2026-11-13首期简化）

正式需求已归档至PRD v1.9第9节，首次使用见其9.8，跨页关系见体验架构2.1。本文只保留运行及验证边界。

- 默认为管理员潘多拉，使用统一成员档案。`account-store.js`维护身份和邀请状态，`account-center.js`承接我的及成员资料，`first-use.js`承接首次激活与两类邀请；识别录入由`people.js`内嵌复用。
- 右上胶囊菜单进入隔离样例，包括首次使用、盒子本地已使用、管理员／普通成员、通用创建邀请、指定认领、链接失效及连接异常；常设恢复正常状态。独立样例不写回默认实例，默认实例数据在恢复后保留。
- 管理员生成邀请后，可从胶囊菜单切到该邀请的接收方，共用同一成员及记忆状态。链接由本地会话保存的邀请ID承接，24小时及单次使用为Mock参数；复制链接不代表跨用户、跨浏览器或真实微信分享可用。
- 普通默认入口刷新恢复预置；隔离账号样例以sessionStorage在同一浏览器会话续接，媒体可转换为本地Data URL。不是服务端持久化，不保证换浏览器或跨设备可用。
- 旧的未完成认领申请仅从演示状态移除，不因迁移绑定旧目标身份或开放其个人内容。真实微信登录／分享、同网发现、归属认证、远程服务、服务端权限及识别模型均未接入。
- 11月13日简化后25项状态检查通过，脚本为`.tmp/reviews/miniapp-accounts-20261111/contract-check.mjs`。浏览器已走通通用直接新建、指定直接认领、登录取消及原资料延续；此前首次激活、空家庭、资料草稿及身份／记忆隔离证据见账号任务。本次文档归档不重复运行浏览器或生产验收。


## 场景照料实现范围

首页顺序为“外出照看、睡眠守护、长辈关怀”。开工与当前迭代见体验架构第4.1～5节，验收由设计任务维护；已归档至PRD 3.3；本文仅维护运行样例与实现边界。

- 650px上滑面板保持照料说明、两三项照料事项和底部双按钮。开始后留在原面板，主操作原位切换为结束，补充／纠正始终保留。外出／睡眠不要求统一人物、空间或时间表单，长辈首轮只明确对象，后续沿用。
- 三场景可并行，头部按名称或数量进入管理。安排按照料事项、介入条件和处理方式组织；共享空间活动、设备反馈和温湿度收进默认折叠的“参考的家庭信息”，可按需展开，不以设备数量或固定参数作为事项标题。不预设主卧、固定亮度、2／4小时时长或固定喝水任务。人物位置未知不绑定房间，来源缺失保留未知。
- 外出照看围绕离家后的设备与家庭状态检查、遗漏处理及无人期间的异常变化。点击即可开始，不设人工无人确认；有人／未知时继续检查，但不按全屋无人执行动作，不改写传感器。安排为离家遗漏处理、家庭环境照看、无人期间异常照看；依据中保留设备参数、在场／环境与离线来源和安全信息缺口。门窗、烟雾、燃气及漏水未接入，相关风险保留未知，不把活动反馈当入侵或家人回家。
- 睡眠安排围绕休息环境、用灯与设备打扰、必要提醒；长辈关怀围绕日常环境、生活安排、需要照应的变化。用户明确的范围、保留要求和提醒在对应事项下简述；检查重点保留在依据与新理解，事项下不重复展示，不替换为设备盘点；实际执行与提醒反馈单独保留，当前依据不作为执行结果。依据展开后，实时更新保留展开状态与阅读位置。
- “最近服务小结”已移除，改为按需出现“小元的新理解”。仅新增或实质修订的可复用偏好／习惯／照料方式进入，每条显示未来作用及来源；同源更新，不重复新增，实际看过的版本离开后不重复呈现。默认至多三条新变化，不设历史列表；无新增时隐藏。
- `scenario-preview-data.js`预置三条本地虚构交流样例：外出优先核对客厅空调、休息时不安排生活提醒、妈妈自行安排生活节奏。首次进入对应场景可直接查看，妈妈样例只在选择妈妈后呈现；与家庭记忆同源，可展开来源、纠正、停用并体验已读隐藏，不创建关注照料卡，不代表真实学习或家庭事实。检查优先级不缩小家庭范围、不授权自动关停。
- 外出默认不保留照明，也不统一关停设备；补充入口可说“这次关闭客厅空调”“这次关闭客厅主灯”，确认后请求控制，回执更新同一具体服务事件。明确保留某处照明只作为用户特别安排，长期自动执行的适用条件另行设计。
- 本地有限解析仅从确实理解的长期表达及用户主动说明的习惯提炼；含糊表达澄清。单次读数、设备动作和使用次数不生成习惯，旧“两次重复”逻辑已移除。尚未接入真实模型或观察学习。
- 新理解进入同源家庭记忆，可从补充入口修改或停用，记忆页修订在相关场景重新理解；相同内容不产生新提示，停用不再沿用。个人记忆不进入家庭场景，修正不改写历史执行。
- 开始前补充只改变待开始草稿，不执行设备、不写记忆；关闭即放弃。开始后确认的设备请求等待约900ms反馈，面板保留简短结果；新的自然语言时效才产生到时结束，无统一隐藏倒计时。
- “小元的关注照料”仅承载具体服务事件和设备执行。场景启停／普通读数／记忆／泛交流不建卡；具体调灯按独立请求ID从等待到回执更新同一事项，场景结束后晚到结果仍保留，不复活场景或重复建卡。现有设备服务、连接恢复及明确成果保留，纯方案讨论退出卡片。
- 喝水等提醒需用户明确安排，到时形成独立具体事件；准备、知晓或取消更新同一事项，不宣称已通知本人或完成喝水。不将普通在场信息表达为跌倒识别。
- 启动／调整／结束等仍在全部记录中保存，但不进入关注照料；每次开始约12秒后的一次共享Mock信息变化更新参考依据及必要安排，不生成学习记录或照料卡。
- 仍为402×874静态Web原型，刷新复原；真实微信运行时、模型、ASR、HA、后台照料、通知及跨端同步尚未接入。相关浏览器与语法验证见设计任务本轮验收，本轮文档统合未改电视或原型实现。

## 事件类调整与纠正实现范围

- 2026-10-22用户确认的简化增量：单项设备继续使用原“恢复调整前／自定义调整”；围绕共同目标组织的事件以显式事件语义区分，卡片及原因详情只有“调整或纠正”入口，不按设备数量机械分类，也不提供整件事一键恢复。
- 新增一条虚构协同事件“已为客厅观影调整灯光和净化”，引用客厅主灯35%与空气置地机低噪的共享初始状态，放在同一列表。它只作为本地历史样例，不在打开首页时发出控制，不代表真实环境目标已达成；原有单项设备样例保留。
- `event-adjustment.js`／`event-adjustment.css`提供650px对话式上滑面板：引用事件标题及一句结果，询问“想怎么调整，或者哪里理解错了？”。输入器复用通用渐变边框、黑圆底主按钮和voice.svg，空输入为语音、有效文字切发送；语音仍为选择样例后模拟转写，结束仅回填，用户可编辑后发送。原普通会话和记忆语音路径未改。
- 文字与语音同路，先复述具体修改及保留范围，在原对话内“确认修改”；用户可继续补充或取消。未确认关闭不执行，已有方案不会通过新草稿的旧确认按钮提交；确认后等待约900ms设备回执，关闭不取消已提交请求，也不强制重新打开面板。返回原因详情保留阅读位置，首页／更多及全部记录沿用同一事件。
- 本地有限解析支持本事件关联设备的灯光百分比／相对亮度、开关、可用净化模式，以及“不是看电视，是在聊天”等判断纠正；含糊、矛盾、无能力或超出事件空间的内容继续澄清，不把未理解的部分忽略后局部执行。只处理这一次，不接长期记忆或多层手动设备配置。
- 方案与执行分开，确认时复核设备状态版本／空间、权限和连接；后续状态变化不被旧方案覆盖。逐项失败如实反馈并保留已完成结果，后续可只重提未完成项；判断纠正只记录在原事件，不伪造设备动作，也不覆盖原执行依据。真实模型／语音／设备及通用事件规划仍未接入。
- 已按2026-10-22用户要求归档至PRD 5.6（v1.8）；跨页职责见体验架构第5节，浏览器与状态边界证据见设计任务。本文保留样例、运行参数和有限解析边界。

## 新增设备接入范围

- 引态入口置于首项，原图`onboarding-int-logo.svg`来自用户提供的logo，仅为裁切添加圆角。用户可见文案不披露“自研设备”，入口两行说明“支持引态协议的设备可自动接入，并识别与盒子的位置关系”，独立页为“自动接入，识别位置关系”：支持引态协议的设备通电并靠近运行中的盒子即可自动加入、识别设备与盒子的位置关系，无账号、扫码、手动搜索或选入按钮。首次进入本地顺序演示等待→连接并识别空间→已自动加入；两台环境感知器／照明控制器只是虚构能力样例。盒子“运行中”和空间识别均为预置结果，未调用真实无线发现、定位、认证或HA；实际距离、协议、精度、多盒子归属及生产异常另行确定。

## 记忆对话实现范围

- 第三个主导航为「记忆」，保留原搜索、全部／短期／长期分类、范围与状态筛选及阅读位置。详情沿用浅蓝渐变头部、402×874标准稿与首页同款裸渐变声纹入口；内容只读，移除表单、使用开关和统一保存按钮。
- 添加入口进入「记下一件事」，直接通过文字或语音告诉小元。不预选范围，小元按明确表达判断个人／家庭归属：个人偏好或归属不明确先保留个人，明确的家庭共同约定可共享；公共空间／设备词不等于全家约定。保存后说明判断结果，可通过对话纠正；明确表达整理保存后直接给出回执及查看记忆入口，有歧义追问必要信息，不再确认后回填详情保存。页头沿用新会话图标作为「记下另一件事」，开始独立记录，不把之前的私人草稿带入新的共享对话。
- 每条记忆按成员分别保存持续的私人对话，与普通会话列表分开；再次打开恢复消息、发言成员、时间、输入草稿和阅读位置。详情只展示当前理解，通过底部入口进入对话后查看及接续历史记录，不在详情另设记录模块，来源／形成依据／历史修正按需展开，不把缺少原始会话的旧来源补造成用户对话。
- `memory-scope.js`使用保守的有限表达规则判断归属，`memory-dialogue.js`处理新增、原位纠正、相同内容去重、必要澄清、停用／恢复、时效及撤销。原始用户表达留在消息与来源中，修改不覆盖旧交流；撤销仅针对仍为最新版本的更新。只改内容不自动恢复已停用／到期条目，到期内容可纠正但仍不继续参考。
- `memory-store.js`继续维护同源记录，按稳定成员标识限制个人记忆；家庭记忆结论由成员共享，相关私人对话、私人来源原话及个人历史仅本人可见。本人可明确调整自己创建的记忆归属，家庭既有约定不由其他成员直接转为私人记录；旧对话按记录归属保留，不控制设备或制造照料卡。
- 原型将记忆及对话作为同一份本地快照写入`sessionStorage`，本标签刷新可恢复，关闭浏览器会话不承诺保留；普通预览与隔离账号体验分别存储。保存失败回滚记忆、保留重试输入，不显示成功。场景理解复用原同源记忆，刷新不重复生成预置记录。
- 语音完整复用现有会话输入器及单次语音浮层：选择示例模拟转写，结束后回填输入框，由用户修改／发送；取消保留原草稿，不调用麦克风或ASR。当前只保存文字记录，不保存原始语音。
- 可用表达覆盖「记住，我睡觉时不喜欢空调直吹」「把这条记忆改为：……」「补充一下，……」「先别用这条记忆」「恢复使用」「先用到下周五」「这条只针对我」「这是全家的约定」等；含具体时间的理解可用「晚一点」触发追问，再回复「23:30」。有限规则不等于真实AI理解、观察学习、召回、长期存储或跨端同步。
